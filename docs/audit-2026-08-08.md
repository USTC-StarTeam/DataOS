## 批次 1 — 预算会计（P0）

三个问题同源于 `_queue_wait_s`（subagent_executor.py:124-153）：

1. **P0：排队抵扣可被永久击穿**。被 cancel 时仍在 PENDING 的 job，sacct 的 Start 列是
   `None`（非代码假设的 `Unknown`/空）→ shell 里 `date -d "None"` 失败 → 用 `$now` 封顶 →
   该 job 贡献的"排队时长"随时间无限增长 → `budget.py:47` 的 elapsed 被冻结 → 10h 预算
   停止永不触发；`_run_one` 的 experimenter timeout 同理被无限延长。集群实证：07-01 以来
   318 个此类 job。触发路径是自愈常规动作（cancel+重提）。
2. **resume 重复抵扣**：budget 语义是 per-invocation 墙钟，但 credit 扫
   `runs_base/<project_id>` 下全部历史 job（无 Submit 下界）——每次 `--resume` 把之前的
   排队总量再送一遍，预算被动膨胀。
3. **eval 排队不可见**：发现口径是 `slurm-*.out`（job 开跑才存在）+ `-name 'handle.json'`
   （只匹配 dataos-train）；dataos-eval 的 `eval_handle.json` 不匹配 → eval job PENDING
   期间零抵扣，预算照烧、experimenter deadline 照缩——排队豁免设计的反面。

修复方向：sacct 改取 `Submit,Start,End,State`（加 `-X` 滤步记录），ssh 拉回 Python 侧算：
终态未启动用 End 封顶、仍在排队用 now、与 invocation 起点取重叠区间；handle 发现放宽为
`*handle.json`。补单测（cancelled-pending / still-pending / pre-invocation / partial-overlap）。

## 批次 2 — AUTO(-2) 收口（P1）

1. **round-0 baseline 兜底漏钳**：code-fixed baseline plan 不带 eval_limit 且跳过
   `_validate_plan`（loop.py:594-608）→ `_run_one` 落到 -2（subagent_executor.py:392）→
   烘出 `--limit -2`、目录名 `_limitauto`、salvage 路径失配。靠 run_lmeval_eval.py:455
   负数容错才歪打正着。修：baseline plan 写死 `eval_limit=-1`。
2. **fixed 模式不忽略 plan.eval_limit**：spec 优先无条件生效（loop.py:422 +
   subagent_executor.py:392），与 schemas.py:47 "Ignored in fixed-limit runs" 矛盾——
   fixed run 里 leader 顺手填 50 即静默突破评测冻结。修：`_spec_from_node` 在 fixed 模式
   丢弃该字段。
3. **best/final_model 对 eval.limit 盲**：`_scored`/`best_node`（state_tree.py:135-148）纯按
   score 排序，`_read_report` 不读 eval.limit——高方差子集分可压过全量分赢下整棵树、成为
   最终交付。"候选 best 必须全量"目前只有 prompt 层约束。修：`_read_report`/attach 记录
   eval.limit，best 选择全量分优先（或子集分不参与 final 声明）。
