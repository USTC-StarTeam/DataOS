RULES
- Do NOT write `status` or `score` at the top level. The score lives in exactly one place
  (`stages.eval.score`) and the node's status is DERIVED from it: a real number means completed.
- `n_samples` is what the scorer actually scored; `limit` is what was REQUESTED. They differ
  whenever the run is AUTO-sized or gets cut short, and only `n_samples` says how big the
  measurement really was. Giving `sample_size` lets you omit `sampled` — it is derived from it.
- `limit` is required. A subset score is not comparable with a full-benchmark score, and it is
  also systematically noisier — the leader is the one who decides what to do about that, so it
  has to be able to see it. If the run's eval limit is AUTO (-2), record the count you actually
  used, not -2.
- `requested_rows` vs `rows`: a selector with `strict=false` silently returns whatever the pool
  had. If they differ by more than 10%, say so in the data stage's `fixes`.
- On a BASELINE run omit `data` and `train` entirely (a baseline has no data and no training),
  or write them as `{"status":"skipped"}`.
- Extra fields are welcome. If you learned something the shape above has no slot for — where the
  parser lives, what target format it wants, what your pre-check found — add it. The leader sees
  everything in this file.
